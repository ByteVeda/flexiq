## The dependency

```toml
[dependencies]
flexiq = "2.0"
```

SQLite is the default and needs nothing else running — one file, one process.
PostgreSQL and Redis are cargo features:

```toml
[dependencies]
flexiq = { version = "2.0", features = ["postgres"] }
```

## Two things to know before you read them

A task's return value is archived as `job.result`, an `Option<Vec<u8>>`, and
the decoder for those bytes is private to the crate. There is no typed result
read. A program that wants a value back hands it out through a durable step,
writes it somewhere the caller can see, or inspects `job.status` and stops
there — which is what both examples do.

A task body takes its arguments and nothing else. No queue is injected, no
context object is passed. The digest task in the notification example opens its
own handle on the same database, and that is the whole pattern.

<Callout type="info">
  Anything the shell does not wrap is still one import away: `queue.storage()`
  hands back the `StorageBackend` the engine itself runs on, so dead-letter
  listings, stuck-job requeues and step rows are reachable without leaving the
  crate.
</Callout>

you have not enqueued anything yet, or
